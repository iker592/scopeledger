# A one-page website change-order template

A change order should be short enough to read and specific enough to make a decision. You can use this checklist in an email, document or your existing project tool.

CHANGE ORDER [number]
Project: [name]
Date prepared: [date]
Original scope reference: [document/version/date]

Requested change:
[Plain-language summary of what the client requested.]

Added deliverables:
[Itemize the pages, functions, integration setup, content or revision work being added. State the result, not only the activity.]

Boundaries:
[What this addition does and does not include; include dependencies on client content, vendor access or third-party services.]

Fee:
[Fixed amount or rate and estimated hours. State taxes and third-party costs separately if applicable. Do not imply a capped fixed price when the amount is only an estimate.]

Payment schedule:
[Agreed timing for payment.]

Delivery impact:
[Old milestone date, revised date and dependencies. If unchanged, say so explicitly.]

Other agreed work:
[State whether this addition replaces an existing item or adds to it.]

Approval:
[Who approves and the written approval method agreed for this project. Do not start until approval is recorded.]

Status: Draft / Sent / Approved / Declined / Deferred

Illustrative example:

Change 003 adds one booking page with a client-supplied calendar embed and one review round for that page. It excludes custom scheduling logic and vendor subscription fees. Added project fee: $300. Delivery changes from October 20 to October 23, subject to receiving the embed access by October 16. All five original pages remain included. Approval is required by the project’s agreed written method before work begins.

These amounts and dates are fictional examples. Adjust for the work you actually estimate; this template does not determine your agreement’s legal requirements.

Keep a separate payment state. Approved work is not the same as invoiced work; invoiced work is not the same as money received. A simple ledger needs change identifier, status, estimated amount, approved amount, invoice reference and payment received. That distinction helps you see where follow-through is missing.

Research context: freelancers describe using work orders and written estimates even for small changes in [this revision thread](https://www.reddit.com/r/web_design/comments/1frbh25); agencies describe recording change requests even when deciding not to charge in [this agency discussion](https://www.reddit.com/r/marketingagency/comments/1rbpdqi/scope_creep_how_do_you_deal_with_it_when_clients/).
